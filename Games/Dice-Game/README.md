# Kniffel PWA

Small offline scorecard for 2–6 players. English/Thai UI with automatic first-run language detection, manual language selection, automatic totals/upper bonus, local autosave and local high-score list.

Open `index.html` through HTTPS/static hosting. PWA service workers require HTTPS (localhost is also allowed).

Production: https://dicegame.pntr.dev/ (start page https://dicegame.pntr.dev/index.html). Deployed by `.github/workflows/dice-game-ftps.yml`, which uploads via FTPS to `server.cpprotect5.de` and then runs `server/smoke.py` against the account origin (static files, byte-exact) and the public domain (`--public`: Cloudflare-proxied, so HTML is checked by page fingerprint, all other files byte-exact, plus the full online API lifecycle).

New devices start in dark mode; a chosen light/dark theme is saved locally. On browsers that offer PWA installation (`beforeinstallprompt`, e.g. Chrome/Samsung Internet/other Chromium browsers on Android) an "Install app" button appears; it stays hidden when the app already runs standalone.

Hosting note: the docroot `.htaccess` on the server is managed by cPanel (PHP handler) and must contain `RewriteEngine On` + `RewriteRule ^api(?:/|$) - [L]`, otherwise a parent rewrite swallows `/api` and `api/game.php` returns 404. The deploy never uploads or deletes `.htaccess`, `.user.ini`, `php.ini`, `cgi-bin/` or `test.php`, and aborts before uploading if the `/api` exception is missing.

## Players, identities and online games

- **Local game:** the logged-in player can take their own seat (👤); further people at the same device are free-named *local guests* (e.g. Bob) and computers (Beginner / Normal / Expert). Registered account names (L, Pat, any account) and "Computer" cannot be used as free names.
- **Online game:** the server is the authority. The host joins automatically as their account (or as a guest when not logged in). In the lobby the host adds computers, local guests on the host device, open seats (join by code) or invites players that are currently online. Seat types: `account`, `guest`, `local`, `computer`, `invite`, `open`. `account` seats are only ever assigned from a valid login token; a client id alone never authenticates an account, and other seats' client ids are never sent to clients.
- **Presence:** logged-in players send a heartbeat every 25 s while the page is visible (every 8 s while the Lobby is open or an own 1-vs-1 invitation waits for an answer; still one timer) (`action=presence`, TTL 70 s); expired presence disappears automatically, logout / End session removes it.
- **Lobby (👥):** lists the other registered players as *Online* (present and invitable), *In a game* (holds a not-left account seat in a started, unfinished online game active within the last 15 min – not invitable, also not offered for seat invitations; leaving, End game and game over free the account at once) or *Offline* (greyed, collapsed). Presence alone never means available; going offline never removes anyone from a running game.
- **Direct 1 vs 1:** `action=duel` (login required) creates a private online game (hidden from the game list, no open seats, no guests/computers, no seat changes) with the inviter and one invitation seat, re-using the normal invitation TTL. The invitee sees "L invites you to a 1-vs-1 game." and answers with the normal `invite-reply`; accepting starts the game at once with exactly these two accounts (inviter begins), declining closes it and the inviter is told (`presence.outgoing`). The inviter may withdraw (`duel-cancel`); logout / End session withdraws pending 1-vs-1 invitations in both directions. Both accounts' user rows are locked in id order for every invite/accept, so double clicks return the same invitation, parallel accepts start one game, and a simultaneous cross-invitation (L→Pat while Pat→L) is matched into exactly one game. Self-invites, busy or offline targets, a second pending invitation and answers by any other account are refused.
- **Dice:** digital dice are the default and appear only once a game has really started – never on "Who is playing?", in the Lobby, the online setup/seat lobby or while an invitation is pending. Locally "✋ Real dice" switches to physical dice with manual scoring (remembered on the device); "🎲 Dice" switches back to digital dice.
- **Invitations:** only the invited account can accept or decline; accepting is idempotent; invitations expire after 10 minutes or are cancelled when the host removes the seat.
- **Start:** `action=start` (host only) is refused while invitations are pending, drops unfilled open seats and locks the roster. After the start only the player whose turn it is (host for computer and local-guest seats) may update, only its own seat, and nobody can join besides reconnecting players. A reconnecting account gets its seat back on any device.
- **Disconnect vs. leave:** a reload, closed tab or lost network is only a *disconnect* – the seat stays and the device reconnects automatically. **End session** (returns to "Who is playing?", no logout) and **Logout** *leave* the online game (`action=leave`): before the start the seat is opened again (the host leaving ends the lobby game); after the start the seat is marked `left` (scores kept), the account is immediately available again and the other players see "X left the game – waiting for a rejoin". The player can come back via Online → *Rejoin* (`action=join` with the account token, also on a new device / client id; never a second seat). When every human seat has left, the game ends.
- **End game** (`action=close`): the host account (its own seat, no host token needed), the host device (host token) or an admin. It finishes the game, cancels its invitations and frees all accounts; later joins get `not_found` ("Game not found – it may have ended."). Active games without any write for 12 h are finished automatically.
- **Sync and rate limits:** the client sends every change with a 10 s timeout; failures (429 with `Retry-After`, 409 conflicts, network errors) are re-sent with bounded backoff (max. 15 s, `Retry-After` up to 60 s) and shown as a connection notice – never a permanent freeze; a closed game (404) is detected and left. Rate limits use fixed windows computed in MySQL time with separate buckets per account (or device id) plus a higher per-IP ceiling so several devices behind one NAT do not share a budget: `sync` (update) 240/min, `join` (join/rejoin) 40/min, `life` (start/leave/close) 40/min, `social` (create/seat/duel/invite replies) 60/min, `result` 20/min, `login` 8/15 min. Normal sync traffic can therefore never block rejoin, leave or End game.
